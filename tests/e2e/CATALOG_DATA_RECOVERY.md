# Catalog data recovery v13.9

The v13.8 live benchmark failed after 118.97 seconds. Brave displayed matching 13.6-inch M4 listings as well as 15.3-inch alternatives, but search results used wrapped links and no complete product-price evidence was acquired. One retailer consumed most of the test window. This change restricts explicit public redirect destinations to validated HTTPS retailer product paths; opaque or ambiguous wrappers are rejected. The alternate discovery query includes the requested display-size class. Native display-class parsing accepts decimal marketed dimensions and rejects explicit conflicting classes. A 36-second scheduling budget per retailer is checked at fresh strategy decisions; an in-flight browser operation may extend actual elapsed time. The partial report distinguishes time or step exhaustion, unobserved matching destinations and specifications without price. No missing evidence is represented as proof of stock absence. No acceptance predicate was relaxed.

Validation: Rust full regression suite (305 passed, 9 ignored), 21 JavaScript tests, real-browser DOM and catalog grounding fixtures, and independent report evaluator. Live validation is separate from regression results.
